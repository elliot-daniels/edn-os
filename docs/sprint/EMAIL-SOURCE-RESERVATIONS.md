# Source-bound synthetic provisional booking

`EmailDraftStore.reserve_job` holds the protected email draft lock through booking. It validates current draft revision/assessment, synthetic provenance and the existing source/submission association, then uses the existing preview parser to require reliable current scheduling evidence matching the canonical job. Estimated durations stay preview-only. It derives duration, requested date/time and readiness from validated source/answers; source identity/hash/revision are included in the scheduling request hash through the evidence basis. The canonical guard rechecks exact job revision/hash under its lock through ledger publication. Lock order remains draft, requests, ledger.

Existing ledger planning adds every active local hold under its mutation lock. Replay preserves the same receipt; conflicts and stale versions require review. Explicit night work is preserved. No automatic job creation, live Outlook events, customer confirmation, AI call or SharePoint write is added.

The opt-in pilot shows a Reserve synthetic provisional hold button only for an eligible linked job. It creates protected synthetic ledger storage only on request, calls the source-bound adapter, and rerenders to display the verified retained hold. Existing-hold display suppresses another button/proposal. Failures are unconfirmed, never successful appointments. This is a synthetic operator-triggered composed workflow, not autonomous live intake. Later job changes still require reservation reconciliation; no automatic release/rescheduling is implemented.

Nine new regression cases cover concurrent/reopened exact replay with immutable source/job bytes, six unreliable/stale/pending/terminal/changed/live-calendar refusals, explicit night work, and full-app booking/reopen/no duplicate control with byte preservation. Native Windows validates refusal only; hosted Linux is required. Existing association logic is factored into a private helper without weakening its receipt/alias checks.
